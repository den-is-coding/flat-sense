# image-ai-service

Детекция планировок (floor plans) среди фото объявления и связка объявления
с планировкой — issue [#58](https://github.com/den-is-coding/flat-sense/issues/58).

## Как это работает

Классификатор спрятан за портом `internal/floorplan.Detector`
(метод `Detect(image.Image) Verdict{IsPlan, Confidence, Method}`), реализацию
можно заменить, не трогая остальной код. Сейчас работает адаптер
`HeuristicDetector` — эвристики первого этапа:

- светлая/белая подложка, доля тёмных пикселей (линии, текст);
- низкая цветность и небольшое число уникальных цветов;
- длинные прямые горизонтальные/вертикальные отрезки (чертёжная графика);
- отсутствие «фотографических» признаков (насыщенные цвета, шум).

Признаки считаются на даунскейле до 256px. Веса логистической модели
подобраны на размеченном наборе `internal/floorplan/testdata/fixtures`
(140 фото реальных объявлений: 79 планировок / 61 не-план, ручная разметка).
Метрики на нём же фиксирует тест `TestEvalFixtures`: precision 0.938,
recall 0.950 (гейт — ≥ 0.90 по обеим).

Инструменты (разработка/переразметка):

- `cmd/sheet` — контакт-листы по выгрузке парсера для ручной разметки;
- `cmd/fixtures` — сборка fixtures из разметки;
- `cmd/eval` — прогон детектора по fixtures (CSV метрик + список ошибок).

## API

| Метод | Путь | Описание |
| --- | --- | --- |
| GET | `/health` | liveness |
| POST | `/api/detect` | тело — изображение (jpeg/png); ответ: вердикт без записи в БД |
| POST | `/api/ads/check` | `{adId, photos?: [url]}` — проверить фото объявления (по умолчанию `images` из `avito_listings`), вердикты пишутся в `ad_floor_plans` |
| GET | `/api/floor-plan?ad_id=123` | основная планировка объявления (макс. confidence) или `null` |

Пример:

```bash
curl -s localhost:8089/api/ads/check -d '{"adId": 3651684187}'
curl -s 'localhost:8089/api/floor-plan?ad_id=3651684187'
```

## Идемпотентность

Каждое проверенное фото получает строку в `ad_floor_plans` (уникальный ключ
`ad_id + photo_ref`), включая «отрицательные» вердикты. Повторный вызов
`/api/ads/check` не пересматривает уже проверенные фото — досматриваются
только новые.

## CLI

```bash
go run . -check-ad 3651684187          # проверка фото объявления + запись в БД
go run . -check-ad 3651684187 -photos '["https://...jpg"]'
go run . -plan 3651684187              # основная планировка (или null)
```

## Конфигурация

`DB_*` — как в parser-service; `HTTP_PORT` (по умолчанию 8080, в compose
проброшен на 8089).
