# Playbook: парсинг Авито через агента (тестовый режим)

Режим: сбор первых данных без прокси, через браузерную сессию агента на российском резидентном IP.
Приоритеты: **достоверность данных > низкий риск блокировки > экономия токенов**. Скорость не важна.

## 1. Правила (обязательные)

### 1.1. Доступ и блокировки
- Работать **только с российского IP без VPN**. Первый признак бана: заголовок страницы
  «Доступ ограничен: проблема с IP» (у curl — HTTP 429, 403, 439 + тот же текст в теле).
- При блоке **не ретраить тот же URL** — ни разу, ни с другими заголовками. Остановить сессию и
  сообщить пользователю; возобновление — только после смены IP/охлаждения (≥30 мин).
- Одна сессия = одна вкладка браузера, никакого параллелизма. Пауза **3–6 сек** между загрузками
  страниц (`waitForTimeout(3000..6000)` рандомно). Мягкий лимит: **≤ 20 страниц за сессию**.
- Не обновлять страницу повторно (`reload`) без необходимости — каждая загрузка = риск для IP.

### 1.2. URL: ничего не выдумывать
- Слаги категорий содержат хеши Авито (`prodam-ASgBAgICAUSSA8YQ`, `studii-ASgBAgICAkSSA8YQ...`),
  которые меняются. **Запрещено конструировать URL по образцу** — это даёт 404 «Такой страницы не существует».
- Правильный путь: открыть проверенный канонический адрес (`/{город}/kvartiry/prodam`) → применить
  фильтры через UI → дальше работать только с URL, которые вернул сам сайт.
- Фильтры в UI применяются чекбоксами/инпутами; клик по чекбоксу делать по label или по координатам
  (`cua.click` по центру label) — сам `<input>` скрыт стилями и клик по нему вечно «висит».
- Если UI-клик не проходит, НЕ брутфорсить: фильтры уже применённой выдачи читаются из URL
  (параметр `f=` — base64-JSON вида `{"from":7500000,"to":9000000}`).

### 1.3. Извлечение данных — только hydration-JSON
- Единственный источник данных карточки: `window.__staticRouterHydrationData.loaderData["catalog-or-main-or-item"].buyerItem.item`.
  Этот JSON встроен в `<script>` HTML — не ходить по DOM и не парсить вёрстку (классы хешированные и нестабильные).
- Из листинга: список `[data-marker="item"]` (title/price/url/address) — этого достаточно для списка URL.
- Из карточки брать из item: `title, id, url, price.price|formattedPrice, sortFormatedDate, geo.address,
  geo.coords{lat,lng}, geo.references (метро), houseParams.data.items (ЖК/дом), description (HTML→текст),
  imageUrls (4 размера), developerV2, seller.isRealtyDeveloper, breadcrumbs`.
- **Запрещено печатать DOM-снапшоты целиком** (снапшот выдачи ~200 000 символов = сожжённые токены).
  Только `evaluate` с формированием компактного JSON и печать результата.
- Страницы открывать батчами по 3–4, извлекать и **сразу печатать JSON-результат в ответ**:
  глобальные переменные между вызовами НЕ сохраняются.

### 1.4. Достоверность (валидация перед записью)
- Цену хранить числом (из `price.price` или нормализовать `formattedPrice`, убрав пробелы/`&nbsp;`).
  Если в цене есть префикс «от …» — это цена застройщика от минимума, ставить флаг `price_is_from: true`.
- Метро: запись валидна только если есть `time` и/или `line_color`. Если `line_color` отсутствует —
  это район, а не станция: помечать `note` и не считать станцией.
- Кросс-проверки: площадь в title == house_params/описанию; этаж в title == `Этаж: N из M`;
  цена попадает в заданный фильтр. Расхождение → пометить в `warnings`, не молча исправлять.
- Незаполненные поля — `null`. **Ничего не домысливать**: нет года постройки (новостройка) — есть
  `Срок сдачи`, и это норма, не ошибка.
- Не нормализовать текст «на глаз»: описания застройщиков содержат намеренно перемешанные
  латин/кириллические символы (антипарсинг) — сохранять как есть, очистку делать отдельно.
- Результат: валидный JSON (проверить `json.Valid`/`python3 -m json.tool`), поля в едином schema-виде,
  `meta` с датой, параметрами выборки, путём извлечения и всеми нестандартными случаями.

### 1.5. Фото
- Ссылки — `item.imageUrls`, размеры: 1280x960 (основной), 640x480, 150x110, 75x55. Качать 1280x960.
- CDN `img.avito.st` не требует кук/реферера — достаточно User-Agent. Качать после основного прохода,
  тем же темпом (паузы), не более 5–10 фото за сессию.
- Формат определять по магическим байтам (JPEG/WebP), расширение не гарантия.

## 2. Готовый промпт для следующего прогона

```text
Задача: спарсить N объявлений на Авито и сохранить структурированный JSON.

Параметры:
- Город: {city_slug} (например, sankt-peterburg)
- Фильтры: {фильтры текстом, например: студии, цена 7 500 000–9 000 000 ₽, год постройки от 2000}
- Сколько объявлений: {N}, детальные данные по каждому
- Файл результата: services/parser-service/internal/avito/testdata/avito_{city}_{дата}.json
- Фото: {да/нет}; если да — в testdata/avito_images/{avito_id}_{n}.jpg

Порядок работы:
1. Проверь доступ: открой в браузере https://www.avito.ru/{city_slug}/kvartiry/prodam.
   Если заголовок «Доступ ограничен: проблема с IP» — СТОП, сообщи пользователю, не ретраи.
2. Примени фильтры через панель фильтров сайта (чекбоксы кликать по label/координатам, не по input).
   Дальше используй только URL, которые вернул сайт. Не изобретай слаги и хеши.
3. Из выдачи извлеки через page-evaluate первые N позиций: title, url, price, address.
   НЕ печатай DOM-снапшоты целиком — только компактный JSON-результат.
4. По каждой карточке открой страницу (пауза 3–6 сек между загрузками) и извлеки ВСЁ из
   window.__staticRouterHydrationData.loaderData["catalog-or-main-or-item"].buyerItem.item:
   title, id, url, price (числом), published, geo.address, geo.coords {lat,lng},
   geo.references → metro[] {station, distance, time, line_color},
   houseParams.data.items → словарь «title → description»,
   description (убрать HTML-теги, не исправлять перемешанные буквы),
   images_count, developerV2 (description/id/trustCard.title), seller.isRealtyDeveloper, breadcrumbs.
   Открывай по 3–4 карточки за вызов и сразу печатай собранный JSON — состояние между вызовами не живёт.
5. Валидируй каждую запись: цена числом и в диапазоне фильтра; метка price_is_from если «от …»;
   метро валидно только при наличии time/line_color (иначе это район — пометить note);
   площадь/этаж из title совпадают с параметрами; отсутствующие поля = null, ничего не домысливай.
6. Собери итоговый JSON: meta (дата, город, фильтры, путь извлечения, нестандартные случаи) + items[].
   Проверь валидность JSON и сохрани в файл.
7. Если были фото: скачай по 1280x960 с паузами, формат проверь по магическим байтам.

Ограничения: без VPN; одна вкладка; ≤20 страниц за сессию; при любом блоке (429/403/439,
«Доступ ограничен», капча) — СТОП и отчёт пользователю; никаких повторных попыток заблокированного URL.
```

## 3. Чек-лист перед завершением сессии

- [ ] JSON валиден, схема едина, все `null` объяснимы
- [ ] В `meta` зафиксированы параметры выборки и все аномалии
- [ ] Нет в чате полных DOM-снапшотов (только компактные JSON-результаты)
- [ ] Ни одного ретрая заблокированного URL
- [ ] Файлы лежат в `services/parser-service/internal/avito/testdata/`
