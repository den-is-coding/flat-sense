# analyzer-service

Оценка конкретного объявления (продажа студии) по окупаемости с учётом
меблировки — issue [#64](https://github.com/den-is-coding/flat-sense/issues/64).
Методика сопоставления — правила кластеризации из [#55](https://github.com/den-is-coding/flat-sense/issues/55).

## Как считается

1. У входного объявления (продажа) определяется меблировка:
   признаки объявления (params) + эвристика по описанию (`internal/evaluate/furnishing.go`,
   правила зафиксированы юнит-тестами). **Сомнение трактуется консервативно
   как «без мебели»** и помечается в отчёте (`furnishingNote`).
2. Строится арендный кластер: студии **того же дома** (ключ — id дома из
   `geo.addressLinks.houseLink`; фолбэк — нормализованный адрес) в диапазоне
   площади **±AreaTolerancePct** от входного объявления, разбитые по мебели:
   «без мебели» / «с мебелью». Объявления аренды с неопределённой мебелью
   остаются в кластере, но в строгие группы сценариев не попадают.
3. Сценарии (цены — медианы групп, вилка p25–p75):
   - **«без мебели»** (если у объявления мебели нет): аренда = медиана
     немеблированных аналогов; окупаемость = цена / (аренда × 12);
     доходность = аренда × 12 / цена.
   - **«с мебелью (после меблировки)»**: цена для расчёта = цена объявления +
     `FurnishingCostRUB` (по умолчанию 500 000 ₽); аренда = медиана
     меблированных аналогов.
   - Если мебель в объявлении **есть** — только сценарий «с мебелью»,
     без надбавки.
4. Confidence по размеру кластера: `n < MinClusterSize` → `low` + предупреждение;
   `n < 2×MinClusterSize` → `medium`; иначе `high`.

Кластер пуст → валидный исход `no_rent_data` с вежливым объяснением (не 500).

## API

`POST /evaluate` — `{"url": "https://www.avito.ru/..."} ` или `{"adId": 3651684187}`.
Ответ — отчёт (данные объявления, кластер с разбивкой, сценарии, confidence,
предупреждения). Источник — БД `avito_listings` (нужен арендный пул: `deal_type='rent_long'`).

## CLI (локальные прогоны на дампах)

```bash
# оценка студии из выгрузки data/spb-795 по арендному пулу из каталога fixtures
go run . -evaluate 3651684187 \
  -dump-dir ../../data/spb-795/listings,internal/evaluate/testdata/fixtures

# реальная аренда: дампы кампаний {meta, items} из parser-service testdata
# (ЖК «Прайм Приморский», «Сенат»); e2e-тест на них — internal/source/realdata_test.go
go run . -evaluate 8409401832 -dump-dir \
  ../../data/spb-795/listings,../../parser-service/internal/avito/testdata/avito_run_arenda_primprime_2026-10-04
```

`-dump-dir` принимает каталоги через запятую и понимает два формата: экспорт
по объявлениям (`data/<кампания>/listings/*.json`) и кампейновые дампы аренды
`{meta, items}` (`parser-service/internal/avito/testdata/avito_run_arenda_*.json`,
у items площадь/этаж извлекаются из заголовка — в заголовках Авито NBSP
вместо пробелов, нормализуется при разборе; дом сопоставляется по
нормализованному адресу, т.к. у items нет houseLink).

## Конфигурация (env)

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `FURNISHING_COST_RUB` | `500000` | надбавка на меблировку |
| `AREA_TOLERANCE_PCT` | `20` | допуск площади аналогов, % |
| `MIN_CLUSTER_SIZE` | `3` | минимальный кластер для полноценного confidence |
| `DB_*` | как в parser-service | подключение к PostgreSQL |

## Тесты

- юнит-тесты арифметики сценариев (table-driven, числа проверены вручную);
- юнит-тесты эвристики мебели;
- e2e на фикстурах из реальных дамп-данных (`internal/evaluate/testdata/fixtures`):
  реальные студии (Ул. Тамбасова, корп. 2) + арендные аналоги на тех же домах;
  покрывают все сценарии issue: обе строки для «без мебели», единственный
  сценарий для меблированной, отказ без аренды, n<3 → предупреждение.
- e2e на **реальной аренде** (`internal/source/realdata_test.go`): студия
  8409401832 (Парашютная ул., 71к2, 7 990 000 ₽) против 10 арендных аналогов
  того же дома из дамп-кампании «Прайм Приморский» (числа проверены вручную;
  в реальных объявлениях мебель часто не указана — при пустой строгой группе
  срабатывает фолбэк на медиану кластера с предупреждением).

## Блокер / статус арендного пула

Арендного пула в БД нет (`avito_listings`: 500 sale, 0 rent_long на
2026-10-04), но есть закоммиченные дампы арендных кампаний
(`parser-service/internal/avito/testdata/avito_run_arenda_*` — «Прайм
Приморский» 24 студии, «Сенат» 34) — на них работает расчёт и e2e-тесты.
Для прод-оценок через `POST /evaluate` нужен импорт арендных кампаний в БД
(парсер поддерживает `rent_long`, у кампейновых дампов формат импорта
`-import`).
